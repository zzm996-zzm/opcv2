# 项目超市真实业务流与接口数据设计

## 目标

把设计稿中的页面还原为真实业务流程中的状态与分支，同时确保机会、案例、项目拆解、匹配问题和匹配结果来自后端接口，而不是前端硬编码。生产界面不提供设计状态目录或调试入口。

## 页面结构

- 主流程为“项目超市 → AI 匹配 → 按需补充提问 → 当前会话的匹配结果 → 已发布项目详情”。匹配会话 ID 始终保留在 URL 中，刷新后仍读取同一条服务端记录。
- 匹配历史根据记录状态进入补充提问或匹配结果；收藏、对比、导出都从当前记录或当前项目上下文触发，不提供脱离上下文的页面目录。
- 项目详情的“成功路径、当前数据、优劣势、可学经验、要避免的行为”使用 URL 查询参数驱动 Tab，页面刷新和分享链接后仍保持当前状态。
- 项目诊断只从项目详情打开；导出只从已完成匹配结果打开；付费弹层只在进入受限内容时打开，并提供返回来源页的关闭入口。

## 数据流

- 数据库迁移为 `project_opportunities` 和 `project_cases` 写入可重复执行的演示目录数据。
- 首页、机会探索、案例库、项目详情和项目对比继续使用现有 `/api/v1/projects/*` 接口读取数据。
- AI 匹配把已发布项目目录提交给模型，返回结果绑定 `opportunity_slug`，避免生成无法进入详情页的虚构项目。
- 补充问题、答案、匹配结果、收藏和导出均绑定匹配会话接口；空列表固定返回 `[]`，避免前端把 `null` 当数组处理。
- 详情 Tab 内容按接口返回的章节标题映射，不在前端复制业务内容；缺少某章节时显示明确空状态。

## 验证

- 扩展 `ProjectsPage` 测试，覆盖无页面目录、会话路由、详情 Tab、接口章节、诊断、对比和导出流转。
- 运行 Web 单测、构建和 Go 测试。
- 启动本地服务，以 1672×941 参考尺寸逐页截图，并在 390px 宽度检查溢出、Tab、操作区和弹层布局。
