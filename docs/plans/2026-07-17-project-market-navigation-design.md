# 项目超市页面可发现性与演示数据设计

## 目标

让设计稿中的 16 个页面状态都能从项目超市内部找到并直接访问，同时确保机会、案例和项目拆解展示数据来自后端接口，而不是前端硬编码。

## 页面结构

- 首页保留现有三个核心入口，并增加“全部页面”导航区，覆盖 AI 匹配、补充提问、匹配结果、历史收藏、付费态、详情五个 Tab、项目诊断、对比和导出。
- 项目详情的“成功路径、当前数据、优劣势、可学经验、要避免的行为”改为 URL 查询参数驱动的独立 Tab 状态，页面刷新和分享链接后仍保持当前状态。
- 新增项目诊断弹层路由，保持设计稿中的遮罩弹层形态，并提供返回详情的关闭入口。

## 数据流

- 新增数据库迁移，为 `project_opportunities` 和 `project_cases` 写入可重复执行的演示目录数据。
- 首页、机会探索、案例库、项目详情和项目对比继续使用现有 `/api/v1/projects/*` 接口读取数据。
- 详情 Tab 内容按接口返回的章节标题映射，不在前端复制业务内容；缺少某章节时显示明确的空状态。

## 验证

- 扩展 `ProjectsPage` 测试，覆盖全部页面入口、详情 Tab 切换、接口章节渲染和诊断弹层。
- 运行 Web 单测、构建和 Go 测试。
- 启动本地服务，在桌面与移动端截图检查入口可见性、Tab 状态和弹层布局。
